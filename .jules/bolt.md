# Bolt's Journal

## Performance Learnings

- **Array allocation overhead in hot paths**: Standard JS array operations like `[...query]` or `slice(0, count).sort(...)` inside tick update loops (60 FPS) generate massive GC pressure. Zero-allocation patterns, such as reusing array structures with `arr.length = 0` and implementing custom in-place sorting (e.g., Shell Sort), significantly reduce frame times.
- **Query Caching & Frozen Arrays**: In development (`__DEV__`), core components and entity arrays are frozen via `Object.freeze` to protect against side effects. In production, we can safely bypass these allocations by caching and reusing pre-allocated arrays under internal fields like `_cachedEntitiesArray` or `_sortedEntitiesArray` without breaching types or determinism.
- **World Command Buffer queue swap**: Re-assigning `this.commands = []` on every frame flush allocates a new array. Swapping `commands` with a pooled array (`commandsPool`) and resetting it via `length = 0` prevents allocations completely.
- **Direct Component Mutators & Allocations**: Using `world.getMutableComponent` instead of `world.mutateComponent` completely avoids allocating callbacks/closures inside hot simulation loops (such as Trail, Animation, TTL, ScreenShake, Particle, Juice, Combo, Invulnerability, StateMachine, and HitDetection systems) and removes redundant lookups.
- **Guarding Mutators with Read-Only Checks**: Because `getMutableComponent` automatically increments `stateVersion`, systems must read components with read-only `getComponent` first, and only invoke `getMutableComponent` if a mutation is actually going to be performed. This keeps resting-state `stateVersion` overhead to exactly zero (verified in SpatialPartitioningSystem & CollisionSystems on 2025-05-15).
- **Physical Collision System Optimizations**: In-place cleaning of `CollisionEvents`, reusing `tempQuery` array for viewport culling filtering, caching CCD candidates, and using in-place `splice` instead of allocating new arrays via `filter` achieves a completely zero-allocation hot-path for standard frames in `CollisionSystem2D` and `CCDSystem`.
- **Viewport Filtering Redundant Calculations**: Querying cameras and computing viewport dimensions (`SpatialCullingSystem.getViewport()`) on every single entity in a filtering loop creates massive CPU and allocation overhead. Computing this boundary once per filtering session reduces camera query operations and boundary allocations by 99.9%.
- **Gating Empty/Idle Component Clearances**: Standard cleanup passes (such as clearing `CollisionEvents` list arrays on every frame, or updating camera `VisualOffset` back to `(0, 0)`) can generate hundreds of state updates/version increments per tick. Gating these with a read-only empty check first ensures that resting entities generate exactly zero stateVersion updates, drastically improving performance during resting/idle simulation ticks.
- **Eliminating Array Spreading & Higher-Order Loops in Systems**: In systems like `HitDetectionSystem`, combining `activeTriggers` and `colPairs` via array concatenation/spreading (`[...activeTriggers, ...colPairs]`) or `.map()` / `.filter()` generates per-hitbox per-tick heap allocations. Replacing these with sequential indexed loops and direct query checks achieves zero allocation per tick.
- **Zero-Allocation Trigger Exit Parsing**: In `CollisionSystem2D` trigger exit processing, replacing `.split(",").map(Number)` with `indexOf(',')` and `substring()` number parsing avoids allocating string and number arrays during trigger exit events.
- **Direct Mutator Access & Value Gating**: Replacing `world.mutateComponent` with `world.getMutableComponent` and gating mutations on read-only value checks (e.g. `steering.mode !== targetMode` or `transform.rotation !== aimAngle`) completely eliminates callback closure allocations and avoids bumping `stateVersion` on unchanged entities.
- **BroadPhase Tuple Pairs & Collision System Frame Sets Buffering**: In physics and collision resolution systems (`BroadPhase`, `CollisionSystem2D`, `AsteroidCollisionSystem`, `SpaceInvadersCollisionSystem`, `SpaceInvadersFormationSystem`, `BoundarySystem`, `PongCollisionSystem`, `CombatSystem`), replacing per-tick tuple allocations (`[a.entity, b.entity]`), local `Set` instantiations (`new Set<string>()`, `new Set<number>()`), helper object literals (`{ [type1]: entityA, [type2]: entityB }`), and `Map` instantiations (`new Map()`) with static/instance reusable pools (`pairsPool`, `currentFramePairs`, `processedPairs`, `destroyedEntities`, `pairResult`, `columnShooters`/`shooterPool`) and sequential indexed loops completely eliminates per-tick heap allocations during physics updates and collision handling while preserving 100% fixed-timestep determinism and rollback safety.
- **Resource Array Reuse & Value-Gated Component Updates**: In `SpatialCullingSystem`, `TilemapRenderSystem`, `JuiceSystem`, `PlatformerCoyoteSystem`, `EnemyBehaviorRegistry`, `EnemySensorSystem`, `InvulnerabilitySystem`, and `ComboSystem`, checking current component values before acquiring `getMutableComponent` or calling `mutateComponent` eliminates per-tick array spread allocations and prevents unnecessary `stateVersion` bumps when simulation states remain static.
- **Single-Player Fast Path & Trigger Indexing**: In `CollectibleSystem` and `CheckpointSystem`, caching single player references (`players.length === 1`) and using indexed matching avoids $O(N \times M)$ `players.includes()` linear array scans per collectible and checkpoint entity every tick.
